Every skill gets an evidence trail.

A reusable, outcome-first way to design, run, inspect, and improve evaluations for Ascent skills and future agent harnesses.

The evaluation loop

A skill is not evaluated by whether it followed one preferred sequence. It is evaluated by whether it produced the right safe outcome in a controlled environment—and whether that remains true as the skill, tools, and model change.

Profile

Know the contract

Capture purpose, inputs, outputs, tools, environment, state boundary, safety constraints, and observable success conditions. Missing facts become insufficient-information, never invented requirements.

Tasks

Test both directions

Pair positive cases with “must not” cases. Include edge cases and a reference solution where a concrete answer exists. A task must be solvable from its prompt and fixture.

Evidence

Learn from every run

Keep results, artifacts, and transcripts. Review failures, close calls, and grader disagreement to separate agent problems from a broken task or grader.

Choose coverage intentionally

What should this suite tell us?

Start from behavior and product risk, not framework preference. A task can move from difficult capability coverage into continuous regression coverage only after it becomes reliably solvable.

Capability

“Can the skill do this useful but difficult new thing?” Expect headroom; use results to guide improvement.

Regression

“Does the skill still do what users already rely on?” Require a near-perfect baseline and run continuously.

Hybrid

Protect trusted behavior while hill-climbing a new capability. This is the default for an evolving skill.

Reliability for non-deterministic agents

One trial

Use for deterministic scripts such as the current project-context runner. Report outcome pass rate and duration.

pass@k

Use when one good attempt is enough—for example, a research assistant offering several candidate paths.

pass^k

Use when every repeat must succeed—for example, a customer-facing workflow with no tolerance for sporadic failure.

One contract, multiple harnesses

The canonical Ascent scaffold is framework-neutral. This avoids coupling a reusable skill to one host while retaining a direct path to richer agent evaluation infrastructure.

1

Ascent task contract

skill-profile.json, eval-plan.json, and cases/tasks.jsonl define portable behavior, fixtures, graders, trials, and metrics.

2

Deterministic runner

Python or host-native tests execute outcome checks in a fresh workspace. The migrated project-context suite is this first regression package.

3

Inspect adapter

Map task records to a Dataset; map the harness to a Solver or ReAct agent; map outcome checks to Scorers; use Docker for sandboxed tool calls.

4

Run review

Use run logs and transcript review to diagnose failures, update failure modes, and promote reliable capability tasks into regression coverage.

Inspect recommendation: adopt it as an optional adapter for multi-turn, tool-using, or repeated-trial suites—not as a mandatory dependency of every Ascent skill. Resolve package availability, sandbox access, host bridges, model credentials, and log-retention policy before direct production adoption.
