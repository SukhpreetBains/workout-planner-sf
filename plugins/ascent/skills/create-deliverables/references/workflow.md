# Workflow

The active workflow is evidence, intake, questions, draft, validation,
customization choice, and delivery.

1. Load the selected template's ordered modules and question definitions.
2. Search extracted workspace documents and project-context evidence.
3. Record source-backed answers with citations in the separate intake file.
4. Show required gaps by module and offer a repeatable missing-document loop.
5. Ask remaining required questions one at a time.
6. Show optional gaps and ask whether the user wants to answer them. If not,
   record that they were skipped and continue.
7. Draft presentation content from the resolved intake and module mappings.
8. Build the branded microsite as the human-readable editorial review.
9. Iterate until accepted, then ask whether the user wants customizations.
10. Detach confirmed custom work into local editable source. Keep all safety
    gates, but stop enforcing the original modules and template.
11. Follow `delivery.md` for the final handoff.

Read `template-system.md` for schema and gap-state details. The user can
explicitly override required gaps after multiple warnings. Such gaps remain in
the intake, build manifest, opening summary, and affected sections. Never invent
content to make an incomplete template look complete.
